## 一、本轮范围与原则

1. **只做前端**：以微信小程序 C 端（PRD 5.1 节 MP-01 ~ MP-09 的 P0 项）为界面蓝本，先看样式和交互流程。
2. **后端全部 Mock**：所有接口由前端 Mock 层模拟（含模拟支付、状态流转、库存扣减），**不写任何真实后端代码**。
3. **接口先行**：每新增一个接口，必须同步登记到《接口文档》，保证"改接口只改一处文档 + 一处 Mock"。
4. **可迁移**：界面按移动端单列布局实现，交互与数据结构对齐小程序；后续迁移微信小程序或接入真实后端时，仅需替换 API 层实现。

## 二、技术方案

| 项 | 方案 | 说明 |
| ---- | ---- | ---- |
| 页面形态 | 纯 HTML + CSS + 原生 JS 单页应用（hash 路由） | 无构建依赖，双击 `frontend/index.html` 即可在浏览器预览，无需安装任何环境 |
| 预览样式 | 桌面端以"手机壳"居中展示，窄屏自动全屏 | 还原小程序视觉比例 |
| Mock 层 | `js/mock.js`：内存状态 + localStorage 持久化，模拟网络延迟、支付成功、状态机流转 | 支付、喷射核销、发券、退款等业务规则均按 PRD 模拟 |
| API 层 | `js/api.js`：业务函数统一出口 | 接真实后端时只改此文件，页面代码零改动 |

## 六、验收标准（M1）

1. 浏览器直接打开 `frontend/index.html`，无报错，主流程可完整点通：首页选香 → 详情 → 模拟支付 0.5 元 → 冲洗动画 → 5 次喷射递减 → 完成发券 → 用券下单正装（19.9 − 3 = 16.9）→ 订单列表可见；
2. 售罄/维护中香型不可试，按钮置灰并有角标；
3. 未使用的试香凭证可申请退款，状态同步到订单列表；
4. 刷新页面后订单、优惠券数据仍在（localStorage 持久化）；
5. 《接口文档.md》覆盖 Mock 层全部接口，且与 `js/mock.js` 实际实现一致。

## 七、Mock → 真实后端替换策略

1. 所有页面只允许调用 `js/api.js` 导出的业务函数，禁止直接调用 `MockBackend`；
2. 接真实后端时，将 `api.js` 内部实现由 `MockBackend.call(...)` 替换为 `fetch(...)`，函数签名与返回结构保持不变；
3. 支付、喷射等需要终端/微信能力的位置，代码中已留 `// TODO(wx)` 注释标记；
4. 接口变更流程：先改《接口文档.md》→ 再改 `mock.js` → 最后调整页面。

## 八、风险与说明

1. 当前为**纯样式演示版**：支付、喷射均为前端模拟，不接真实硬件与微信支付；
2. 喷雾页的"酒精冲洗 2~3 秒"按 PRD HW-02 以动画 + 接口 `needFlush` 字段模拟，真实时序由终端固件决定；
3. localStorage 数据仅存于本机浏览器，清缓存即重置演示数据。
