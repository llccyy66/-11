## 二、项目背景与产品目标

### 2.1 背景

1. 线下专柜客单价高、心理门槛高，学生群体不敢进店试香；
2. 线上购买只能看文字香调描述，气味主观，踩雷率高。

本项目以「试香纸终端免费引流 + 雾化终端付费试香 + 小程序承接正装转化」为核心逻辑，首期在河北师范大学投放 10 个点位验证模型。

### 2.2 产品目标（试点期）

| 目标 | 指标 |
| ---- | ---- |
| 试点规模 | 河北师大校内 10 个雾化终端点位 + 配套试香纸终端 |
| 单台硬件成本 | ≤ 500 元/台（计划书测算 ≈ 461.8 元） |
| 试香定价 | 0.5 元/次，单次 5 喷 |
| 转化目标（理想值） | 单点位日均售出正装 2 瓶（单瓶 20 元、毛利率 30%） |
| 核心监测指标 | 扫码量、试香付费转化率、正装下单转化率 |

### 2.3 名词解释

| 名词 | 解释 |
| ---- | ---- |
| 终端A | 亚克力试香纸引流终端，20 格试香纸，免费嗅闻，不直接盈利 |
| 终端B | 电控雾化试香终端，20 款香水 + 1 瓶清洗酒精，付费试喷 |
| 冲洗流程 | 切换香型前，自动开启酒精瓶管路冲洗 2~3 秒，防止串味 |
| 单雾化器共用方案 | 21 个储液瓶共用 1 片雾化片，由多路电磁阀切换毛细管路 |
| 试香 | 用户付费 0.5 元，获得 5 次雾化喷射体验 |

## 三、用户角色与核心场景

| 角色 | 描述 | 核心诉求 |
| ---- | ---- | ---- |
| C端用户 | 高校学生为主，预算有限 | 低成本闻香、先试后买、避免踩雷 |
| 运营人员 | 首期单人运营（兼硬件维护） | 低运维成本、远程掌握设备与库存状态、补货提醒 |
| 系统 | 云端后台 + 终端固件 | 指令可靠下发、状态实时上报、异常可降级 |

**核心场景**

1. 学生课间路过教学楼终端 → 扫码 → 浏览香型 → 付 0.5 元试喷 → 体验满意 → 小程序内下单正装；
2. 学生在试香纸终端免费嗅闻 → 扫码查看该香型详情与售价 → 跳转附近雾化终端试喷或直接下单；
3. 运营人员每日查看后台 → 收到某点位香水/酒精低液位提醒 → 携耗材上门补货并登记。

## 四、系统总体结构

```
用户（微信小程序）
      │  扫码 / 支付 / 下单
      ▼
云端后台（订单、设备、商品、数据）
      │  指令下发 / 状态上报
      ▼
终端B（电控雾化试香终端：控制板 + 电磁阀 + 雾化片）
终端A（试香纸终端：无电子件，仅物料二维码 → 跳转小程序）
```

通信约定：终端B 通过 4G/WiFi 联网（校园网环境复杂，建议 4G 模组为 P0），与云端保持心跳，指令走云端中转，不允许多租户直控。

## 五、功能需求

优先级定义：P0 = 试点上线必须有；P1 = 试点期尽快补齐；P2 = 扩张期实现。

### 5.1 微信小程序（C端）

| 编号 | 需求 | 优先级 | 说明 |
| ---- | ---- | ---- | ---- |
| MP-01 | 扫码进入 | P0 | 扫终端二维码进入小程序，自动识别点位与终端编号，展示该终端在售香型列表 |
| MP-02 | 香型列表 | P0 | 展示 20 款香型：名称、前中后调、正装售价、当前可试状态（可试/已售罄/维护中） |
| MP-03 | 香型详情 | P0 | 图文展示香调结构、适用场景、正装价格、「0.5 元试喷 5 次」入口 |
| MP-04 | 付费试香下单 | P0 | 微信支付 0.5 元 → 支付成功后获得 1 次试香凭证（5 喷） |
| MP-05 | 触发喷雾 | P0 | 支付成功页提供「开始试香」按钮，点击后下发喷雾指令，展示剩余喷射次数（5→0） |
| MP-06 | 喷射次数核销 | P0 | 每次喷射由终端上报核销，防止重复触发；凭证当日有效，超时未用支持自动退款 |
| MP-07 | 正装下单 | P0 | 试香完成页引导下单正装（默认自提/宿舍配送，试点期简化物流），微信支付 |
| MP-08 | 优惠券 | P1 | 试香完成后自动发放正装优惠券（如满 20 减 3），下单可抵扣，提升转化 |
| MP-09 | 订单列表 | P0 | 查看试香记录与正装订单状态 |
| MP-10 | 点位地图/引导 | P2 | 展示附近雾化终端点位（配合终端A引流跳转场景） |
| MP-11 | 售后入口 | P1 | 正装订单退款申请入口（单人运营，先做人工审核流程） |

### 5.2 电控雾化试香终端（终端B 固件）

| 编号 | 需求 | 优先级 | 说明 |
| ---- | ---- | ---- | ---- |
| HW-01 | 指令接收与执行 | P0 | 接收云端指令：冲洗 → 切换电磁阀 → 雾化喷射，全流程自动完成 |
| HW-02 | 酒精冲洗流程 | P0 | 每次试香前先切换至 21 号酒精瓶管路冲洗 2~3 秒，再切换至目标香型管路 |
| HW-03 | 管路切换 | P0 | 多路微型电磁阀控制 21 根毛细管路，一次只开通一路，防止混液 |
| HW-04 | 雾化喷射控制 | P0 | 单次凭证 5 次喷射，每次喷射时长固定可配（固件参数），用户通过小程序触发 |
| HW-05 | 喷射计数上报 | P0 | 每次喷射实时上报云端核销；断网时本地缓存、恢复后补传 |
| HW-06 | 状态上报 | P0 | 定时心跳上报：在线状态、各瓶剩余液位估算（按喷射次数折算）、故障码 |
| HW-07 | 低液位提醒 | P0 | 香水或酒精余量低于阈值时上报后台，触发补货提醒 |
| HW-08 | 故障检测 | P1 | 管路堵塞、雾化片异常、电磁阀故障的异常码上报（基于电流/出雾反馈的简易判断，可分期实现） |
| HW-09 | 异常补偿 | P0 | 支付成功但设备出液失败时，自动全额退款或补偿 1 次免费试香券，并提示用户 |
| HW-10 | 离线降级 | P0 | 断网时停止接单（小程序端显示维护中），恢复后自动上线；已支付未核销凭证保留 |
| HW-11 | 安全约束 | P0 | 箱体防漏托盘；酒精单瓶容量受限；设备远离热源安装（安装规范文档另出） |
| HW-12 | 固件远程升级 | P2 | OTA 升级，扩张期多点位运维必需 |

### 5.3 试香纸引流终端（终端A）

| 编号 | 需求 | 优先级 | 说明 |
| ---- | ---- | ---- | ---- |
| PA-01 | 物料配置 | P0 | 5×4 共 20 格，每格对应一款香型：试香纸（独立密封袋）+ 香型名称标签 + 小程序码 |
| PA-02 | 内容一致性 | P0 | 终端A 上的香型集合与小程序/终端B 后台配置保持一致，换香时同步更新物料 |
| PA-03 | 防盗优化 | P1 | 试点采用链条绑定密封袋方案；若盗损率高，切换为封闭嗅闻窗口方案（不出纸） |

### 5.4 后台管理系统（运营端）

| 编号 | 需求 | 优先级 | 说明 |
| ---- | ---- | ---- | ---- |
| AD-01 | 设备管理 | P0 | 终端档案：编号、点位（楼栋/楼层）、绑定香型方案、在线状态、最近心跳 |
| AD-02 | 远程指令 | P1 | 远程下发：暂停服务、恢复服务、触发一次自检冲洗 |
| AD-03 | 香型/SKU 管理 | P0 | 香型上下架、前中后调文案编辑、正装售价、试点价（20 元档）维护 |
| AD-04 | 库存与耗材管理 | P0 | 按喷射次数自动扣减香水/酒精虚拟库存；试香纸库存手工登记；低于阈值推送补货提醒 |
| AD-05 | 补货工单 | P1 | 低液位自动生成补货任务，运营人员处理闭环（领取→完成→拍照留档） |
| AD-06 | 订单管理 | P0 | 试香订单与正装订单查询、退款操作（含 HW-09 自动退款记录） |
| AD-07 | 优惠券管理 | P1 | 券模板配置（面额、门槛、有效期）、发放与核销统计 |
| AD-08 | 数据看板 | P0 | 按日/点位：扫码量、试香付费转化率、正装下单转化率、GMV、毛利率、点位排行（用于淘汰低流量点位） |
| AD-09 | 账号权限 | P2 | 试点期单账号；扩张期支持区域代理子账号与数据隔离 |

## 六、核心业务流程

### 6.1 付费试香流程（主流程）

```
扫码(MP-01) → 选香型(MP-02/03) → 微信支付 0.5 元(MP-04)
→ 云端校验凭证 → 下发指令：酒精冲洗 2~3s(HW-02) → 电磁阀切换(HW-03)
→ 用户点击喷雾，雾化片出雾，喷 1 次核销 1 次(MP-05/HW-04/05)，共 5 次
→ 试香完成 → 发放优惠券(MP-08) → 引导下单正装(MP-07)
```

异常分支：

- 支付成功但设备离线/故障 → 自动退款或补偿券（HW-09），后台留痕（AD-06）；
- 用户支付后当日未使用 → 次日自动退款（MP-06）；
- 喷射中途断网 → 本地缓存计数，恢复后补传（HW-05）。

### 6.2 正装购买流程

```
试香完成页 / 香型详情页 → 立即购买 → 填写收货信息（试点期校内自提/配送）
→ 微信支付 → 订单生成 → 运营人员发货/配送 → 订单完成
```

### 6.3 补货运维流程

```
终端液位/耗材低于阈值(HW-07) → 后台提醒/生成工单(AD-04/05)
→ 运营人员携耗材到点位 → 补充香水/酒精/试香纸 → 后台登记补货 → 恢复正常库存扣减
```

## 七、非功能需求

| 类别 | 需求 |
| ---- | ---- |
| 性能 | 用户点击「开始试香」到终端开始冲洗 ≤ 5 秒（正常网络）；后台看板数据延迟 ≤ 5 分钟 |
| 可靠性 | 终端 7×24 无人值守运行；断电重启后自动恢复联网并上报；每日空闲时段自动执行一次管路润洗（防长期闲置堵塞，参数可配） |
| 支付安全 | 全部走微信支付，终端与云端指令带签名防重放，凭证一次性核销 |
| 数据安全 | 用户手机号等个人信息最小化收集，符合微信小程序规范与个人信息保护要求 |
| 安全合规 | 香水/酒精为易燃液体：箱体防漏托盘、限量存放、远离热源；设备安装、审批流程遵循校方规定（见计划书第四章） |
| 成本约束 | 终端B 整机 BOM ≤ 500 元/台；小程序首期采用模板/轻量定制，控制固定投入 |
| 可维护性 | 储液瓶、毛细管、雾化片均为可快换耗材设计；运维操作不要求专业工具 |

## 八、数据指标与埋点

| 指标 | 定义 | 用途 |
| ---- | ---- | ---- |
| 扫码量 | 每点位每日扫码进入小程序的 UV/PV | 衡量引流效果 |
| 试香付费转化率 | 付费试香订单数 ÷ 扫码进入香型页 UV | 定价与选品优化 |
| 正装下单转化率 | 正装订单数 ÷ 完成试香人数 | 核心盈利指标，验证 2 瓶/日假设 |
| 试香→用券率 | 用券下单数 ÷ 发券数 | 验证优惠券策略（MP-08） |
| 点位 ROI | 点位月毛利 ÷ 点位月成本 | 淘汰低流量点位（AD-08） |
| 设备可用率 | 在线时长 ÷ 应在线时长 | 硬件稳定性 |

## 九、验收标准（试点上线门槛）

1. 主流程闭环：扫码 → 支付 → 冲洗 → 5 次喷射核销 → 引导下单，全流程无人工干预跑通；
2. 串味验证：连续试喷 2 款差异大的香型，第 2 款前 1 喷不得有明显前款残留气味（人工嗅辨评审）；
3. 异常退款：模拟设备离线支付场景，退款/补偿券自动到账；
4. 液位与补货：虚拟库存扣减与低液位提醒准确触发；
5. 数据看板：六大核心指标可按点位、按日查询；
6. 安全检查：防漏托盘有效、酒精存放量符合规范、安装经校方许可。

## 十一、外部依赖与风险提示

1. **校方审批**：点位投放须经河北师大后勤/创业孵化部门许可，签署协议后方可装机，属上线前置条件；
2. **供应链**：正装香水货源（20 元档、30% 毛利）需提前锁定，缺货直接影响转化；
3. **支付资质**：小程序需完成微信支付商户开通；
4. **硬件长尾风险**：管路堵塞、雾化片损耗速率需在原型期实测，据此修订维护周期与备件库存；
5. **转化风险**：2 瓶/日/点位为理想假设，试点数据不达标时优先优化选品、定价与优惠券策略，而非直接扩张。
